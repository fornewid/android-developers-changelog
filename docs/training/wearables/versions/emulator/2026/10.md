The Wear OS canary emulator in Android Studio lets you test upcoming platform
features and user interface changes before they become available in a consumer
platform release on physical devices.

The latest emulator system image---published as **Wear OS 7.1** (API level
37.2-beta1,
based on Android 17 `"CinnamonBun"`) in the Android Studio Canary
channel---provides you with an early look at the upcoming system status bar, which
will appear on physical devices in a later platform release of Wear OS.

> [!NOTE]
> **Note:** The system status bar is included exclusively in this canary emulator to support early testing and feedback. It won't be included in the upcoming Wear OS 7.1 stable emulator.

## Prerequisites

Before you set up the Wear OS canary emulator, verify that your development
environment meets the following requirements:

- **Android Studio version:** Use the [latest preview release of Android
  Studio](https://developer.android.com/studio/preview) from the Canary channel (Android Studio Narwhal or later).
- **Android emulator version:** Update to the latest version of **Android
  Emulator** by navigating to **Tools \> SDK Manager \> SDK Tools**.

> [!IMPORTANT]
> **Key Point:** Starting with Wear OS 6, emulator system images are signed builds. You cannot obtain root access (`adb root`) or userdebug logging on these images.

> [!NOTE]
> **Note:** The Wear OS emulator system images might not be available in all regions, such as in China.

## Set up the emulator

To download the system image and create a virtual device in the official
emulator, complete the following steps:

1. Download and open the [latest preview release of Android Studio](https://developer.android.com/studio/preview).
2. In Android Studio, click **Tools \> SDK Manager**.
3. In the **SDK Tools** tab, select the latest version of **Android Emulator** and click **Apply** , then **OK** to install the latest version if it isn't already installed.
4. In the **SDK Platforms** tab, select **Show Package Details** and expand `Android DEV Preview`. Depending on your host machine's architecture (ARM or Intel), select either **Wear OS 7.1 ARM 64 v8a System
   Image (signed)** or **Wear OS 7.1 Intel x86_64 Atom System Image (signed)**, both of which use API level 37.2-beta1.
5. Click **Apply** , then **OK**, to download and install the system image.

   ![Android Studio SDK Manager showing the Wear OS 7.1 system image under Android DEV Preview](https://developer.android.com/static/wear/images/emulator/2026/10/select-in-sdk-manager.png) **Figure 1.** Select the system image for the canary emulator in the SDK Manager.
6. In Android Studio, open the Device Manager by selecting **Tools \> Device
   Manager** . Click **Create device** (or click **Add a new device**
   ![](https://developer.android.com/static/studio/images/buttons/device-manager-add-new-device.png) **\> Create Virtual Device**).

7. In the **Category** (or **Form Factor** ) pane, select **Wear OS**.

8. Select a hardware profile (for example, **Wear OS Large Round** or **Wear OS
   Small Round** ), and then click **Next**.

9. Select the **Wear OS 7.1** system image with an **API** level of
   `Android DEV Preview` and an architecture that matches the one that
   your development machine uses (ARM 64 v8a or Intel x86_64). If the image
   isn't installed yet, click **Download** next to the release name.

10. After the download is complete, or you verify that you already downloaded
    the image, select the image and click **Finish**.

    ![Android Studio virtual device configuration showing the selected item as Wear OS 7.1 API 37.2-beta1 system image](https://developer.android.com/static/wear/images/emulator/2026/10/configure-avd.png) **Figure 2.** Configure the Wear OS canary emulator using the API 37.2-beta1 system image.

### Test your app on the emulator

To run and test your app on the virtual device you created, complete the
following steps:

1. Go to the Android Studio toolbar and select the virtual device.
2. Click **Run** ![](https://developer.android.com/static/studio/images/buttons/toolbar-run.png).
3. Install your app on the virtual device and navigate through your app's user-facing workflows.

## Try out the system status bar

To prepare for an upcoming platform release of Wear OS, this canary emulator
renders a persistent system status bar over Wear OS app windows at the top
position of the circular display. The system status bar displays the current
time and system status indicators. These indicators use standardized clock
typography, placement, and backplate across the platform and different apps,
including your app.

> [!NOTE]
> **Note:** In this early build, the system status bar displays a placeholder star icon instead of final system status indicators.

### Configure your app for the system status bar

The system status bar activates only for apps that do the following:

1. Target API level 35 or higher.
2. Compile against Compose for Wear OS version 1.8.0-alpha02 or higher, or explicitly opt in by updating the manifest file.

### Features of the system status bar

This system implementation of the status bar has several key characteristics:

- **Automatic coordination in Jetpack Compose for Wear OS:** When your app targets API level 35 or higher and compiles against Compose for Wear OS version 1.8.0-alpha02 or higher, `AppScaffold` and `ScreenScaffold` automatically opt your app in to the system status bar.
- **Time text is handled by the system:** `AppScaffold` suppresses its in-app
  `TimeText` clock so that only the system status bar time appears.
  `ScreenScaffold` applies padding to the top status bar window inset, and the
  scaffold hides the status bar while users scroll through list content. After
  about 2 seconds of user idle time, the time text reappears.

  > [!NOTE]
  > **Note:** On devices that run Wear OS 7 or earlier, `AppScaffold` automatically falls back to rendering the `TimeText` that you've previously specified for your app.

- **Full-screen dialogs and immersive mode:** Full-screen interactive
  components in Wear Compose Material 3---including `AlertDialog`, `Dialog`,
  `Stepper`, `TimePicker`, and `DatePicker`---automatically hide the system
  status bar while displayed. For screens that require a full-screen immersive
  experience, use `StatusBarSuppression`.

- **View-based app support (not recommended):** Apps built with Android Views
  can opt in using the `com.google.wear.ENABLE_GLOBAL_STATUS_BAR` tag in the
  manifest file and handle top inset padding and visibility using
  `WindowInsetsCompat` and `WindowInsetsControllerCompat`.

  > [!CAUTION]
  > **Caution:** Android Views is in maintenance mode. We recommend that you migrate your app to use [Jetpack Compose for Wear OS](https://developer.android.com/training/wearables/compose).
