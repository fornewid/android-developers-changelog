# Insights into agent code generation from Android Bench - Speakers: Tomáš Mlynarič (Android DevRel) - Track: Tools \& Performance - Video: https://www.youtube.com/watch?v=rIIAwylLb5Q - Page: https://developer.android.com/events/dev-summit/talks/insights-into-agent-code-generation-from-android-bench ## About the talk AI models can generate entire features in minutes, but is the code correct? We built Android Bench, our AI evaluation benchmark, to answer this question after analyzing thousands of generated code changes. This talk shares insights from our journey, including all the ways we saw models cheats, how prompt specificity leads to higher code quality and how different agents approach the same task. ## Summary - Android Bench 2.0 uses closed-source tasks to prevent contamination and evaluate AI coding agents on complex Android development work. - Evaluation relies on implementation-agnostic UI tests and a Multimodal LLM Judge instead of brittle unit tests or strict pixel-diffing. - Built-in cheating detectors catch agent shortcuts such as test tampering or fake background drawables. Any detected shortcut results in an immediate failing grade. - Cost per task varies widely from advertised token prices because talkative models burn more tokens by repeatedly rebuilding and rerunning. - Frontier models achieve around 80% completion rates but pass only 20% to 40% of tasks due to subtle flaws. ## Resources - \[Why SWE-bench Verified no longer measures frontier coding capabilities\](https://openai.com/index/why-we-no-longer-evaluate-swe-bench-verified) - \[Android Bench leaderboard and benchmarks\](https://d.android.com/bench) ## Topics android-bench, benchmarking,
