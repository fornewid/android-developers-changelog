# Memory troubleshooting with Firebase Crashlytics - Speakers: Polina Govorkova (Senior Software Developer) - Track: Tools \& Performance - Video: https://www.youtube.com/watch?v=2ruqmicLr08 - Page: https://developer.android.com/events/dev-summit/talks/memory-troubleshooting-with-firebase-crashlytics ## About the talk Keep your app's memory footprint lean-and-mean and non-segfaulty with Firebase Crashlytics. This session explores our comprehensive suite of memory troubleshooting tools available in the Firebase console and in Android Studio. We'll start by covering how to leverage ANR insights and GWP-ASan reports to diagnose elusive memory bugs and then dive into our latest tooling for Out-Of-Memory (OOM) and Memory Limiter Kill (MLK) events, designed specifically to help you navigate and adapt to the new memory limits introduced in Android 17. ## Summary - Application Not Responding errors often trace back to background bottlenecks or memory exhaustion rather than active CPU load. Firebase Crashlytics queries \`ApplicationExitInfo\` to surface multithread traces and identify root blocking threads. - Out of memory crashes occur when apps exceed runtime Java heap limits. Crashlytics integrates with Android 17's \`ProfilingManager\` to collect de-obfuscated heap snapshots that can be inspected in Perfetto or through the Android CLI. - Android 17's Memory Limiter terminates individual processes that consume excessive total RAM, including native allocations. Crashlytics groups these terminations on the dashboard alongside heap dumps to help separate C++ memory leaks from managed heap allocations. - Native memory corruption frequently surfaces on system threads rather than in app code. Crashlytics supports GWP-ASan and Arm MTE, and GWP-ASan reports pinpoint exact allocation and deallocation sites for bugs such as use-after-free. ## Resources - \[ApplicationExitInfo API
