 ### Key points about the code
 
-- Obtains an instance of the [`ProcessCameraProvider`](https://developer.android.com/reference/kotlin/androidx/camera/lifecycle/ProcessCameraProvider.md.txt) using the [**projected device context**](https://developer.android.com/develop/xr/jetpack-xr-sdk/access-hardware-projected-context.md.txt#phone-activity-service).
-- Within the projected context's scope, the glasses' primary, outward-pointing camera maps to the `DEFAULT_BACK_CAMERA` when selecting a camera.
-- A pre-binding check uses [`cameraProvider.hasCamera(cameraSelector)`](https://developer.android.com/reference/kotlin/androidx/camera/lifecycle/ProcessCameraProvider.md.txt#hasCamera(androidx.camera.core.CameraSelector)) to verify that the selected camera is available on the device before proceeding.
-- Uses **Camera2 Interop** with [`Camera2CameraInfo`](https://developer.android.com/reference/kotlin/androidx/camera/camera2/interop/Camera2CameraInfo.md.txt) to read the underlying [`CameraCharacteristics#SCALER_STREAM_CONFIGURATION_MAP`](https://developer.android.com/reference/kotlin/android/hardware/camera2/CameraCharacteristics.md.txt#scaler_stream_configuration_map), which can be useful for advanced checks on supported resolutions.
-- A custom [`ResolutionSelector`](https://developer.android.com/reference/kotlin/androidx/camera/core/resolutionselector/ResolutionSelector.md.txt) is built to precisely control the output image resolution for [`ImageCapture`](https://developer.android.com/reference/kotlin/androidx/camera/core/ImageCapture.md.txt).
-- Creates an `ImageCapture` use case that is configured with a custom `ResolutionSelector`.
-- Binds the `ImageCapture` use case to the activity's lifecycle. This automatically manages the opening and closing of the camera based on the activity's state (for example, stopping the camera when the activity is paused).
-- **Configuring for single-stream hardware:** The glasses camera pipeline is constrained to a single active stream at a time. When `ImageCapture` is bound alone, CameraX attaches an internal repeating stream (`MeteringRepeating`) for focus and metering by default, which causes the single-stream pipeline to stall. To bind `ImageCapture` by itself without a preview stream, disable the forced repeating stream by setting [`setRepeatingStreamForced(false)`](https://developer.android.com/reference/kotlin/androidx/camera/core/CameraXConfig.Builder.md.txt#setRepeatingStreamForced(kotlin.Boolean)) on [`CameraXConfig.Builder`](https://developer.android.com/reference/kotlin/androidx/camera/core/CameraXConfig.Builder.md.txt) (for example, by implementing [`CameraXConfig.Provider`](https://developer.android.com/reference/kotlin/androidx/camera/core/CameraXConfig.Provider.md.txt) in your `Application` class or configuring `ProcessCameraProvider` before initialization).
+- **Per-device `LifecycleCameraProvider`:** Use `LifecycleCameraProvider.createInstance` to create an isolated camera provider scoped to the active projected context. Because the projected context's `deviceId` can change when the glasses disconnect and reconnect while your app process stays alive, creating a per-device provider ensures CameraX binds to the active connected device.
+- **Listen for camera presence:** On CameraX 1.6.0 and higher, register a [`CameraPresenceListener`](https://developer.android.com/reference/kotlin/androidx/camera/core/CameraPresenceListener.md.txt) using [`cameraProvider.addCameraPresenceListener`](https://developer.android.com/reference/kotlin/androidx/camera/core/CameraProvider.md.txt#addCameraPresenceListener(java.util.concurrent.Executor,androidx.camera.core.CameraPresenceListener)) instead of opening the camera immediately when the glasses connect. Asynchronous setup between the glasses and host must finish before the OS finishes recreating the glasses' camera, and the glasses' camera can also disappear dynamically while connected (such as during thermal mitigation).
+  - **Camera addition (`onCamerasAdded`):** Fires after [`availableCameraInfos`](https://developer.android.com/reference/kotlin/androidx/camera/core/CameraProvider.md.txt#availableCameraInfos()) is updated with the added camera, avoiding timing races during setup.
